# 配置说明

所有配置从仓库根目录的 `.env` 读取。以 [`.env.example`](../.env.example) 中的字段、注释和示例为准；它包含当前版本完整的可选项。修改配置后通常需要重启相关进程。

## 最小配置

最小可运行配置只需：

1. 设置 `STOCK_CODES`，或在命令行通过 `--stocks` 传入代码。
2. 设置一个 LLM 提供商的 Key，或配置 Ollama。

例如，使用兼容 OpenAI 的服务：

```env
OPENAI_API_KEY=your-key
OPENAI_BASE_URL=https://provider.example/v1
OPENAI_MODEL=your-model
```

不要照抄示例中的模型、地址或密钥占位符到生产环境。提供商支持、模型路由与回退由当前 `.env.example` 和运行时诊断决定。

## 配置层次

系统依次从环境变量与 `.env` 加载配置；服务内会将已解析配置提供给 CLI、API、任务和通知模块。Web 设置页可管理被配置注册表允许的字段，但它不替代部署环境中的密钥管理。

| 范畴 | 典型字段前缀 | 用途 |
| --- | --- | --- |
| 自选股与报告 | `STOCK_`、`REPORT_` | 分析范围、报告语言与展示。 |
| LLM | `LLM_`、`OPENAI_`、`GEMINI_`、`ANTHROPIC_`、`OLLAMA_` | 模型、渠道、回退和生成参数。 |
| 数据源 | `TUSHARE_`、`TICKFLOW_`、`FINNHUB_`、`LONGBRIDGE_` | 不同市场的数据增强与数据源优先级。 |
| 搜索与资讯 | 搜索服务对应字段 | 新闻、公告与事件检索。 |
| 通知 | `NOTIFICATION_` 及渠道前缀 | 推送路由、静默、去重和各渠道凭据。 |
| 服务与存储 | `DATABASE_`、`API_`、`WEBUI_` | 数据库、监听地址和 Web 托管。 |
| 用户模式 | `USER_`、支付相关字段 | 多用户认证、配额和计费能力。 |

## LLM 与回退

可使用单个提供商，也可用 `LLM_CHANNELS` 声明多个渠道。每个渠道可以拥有独立的协议、地址、Key 与模型列表；当主模型不可用或结果不符合要求时，系统会尝试配置的回退路径。运行时不会为了某次请求改写 `.env`。

建议先用一个模型跑通单次分析，再逐步添加渠道与回退。Web 设置页的连接测试、服务日志和 API 诊断结果是排查模型问题的首选依据。

## 数据源

系统通过 `backend/data_provider/` 聚合多家数据源。不同市场、字段和数据源可用性不同，某个源失败时分析流程通常会使用后备源或缓存继续执行。没有配置付费数据源时，基础能力仍可使用公开数据源，但数据完整性、实时性和稳定性会下降。

配置密钥前应确认其市场覆盖和服务限额。不要把单一数据源视为绝对真源，尤其是在停牌、盘前盘后或网络受限场景。

## 通知

通知由 `NOTIFICATION_CHANNELS` 和对应渠道凭据决定，支持 Webhook、邮件、IM Bot 与自定义 Webhook 等实现。先配置一条渠道，再运行：

```powershell
uv run --locked python backend/main.py --check-notify
```

该命令只检查配置，不发送消息。Web 设置页可对单个渠道发送真实测试消息，测试值不会保存到 `.env`。通知失败不应中断分析主流程；详细排查见[运行与部署](operations.md)和[常见问题](FAQ.md)。

## 安全边界

- `.env`、数据库备份、日志和报告都可能包含敏感信息，必须限制访问权限。
- 前端可读配置与服务器密钥不是同一安全边界；不要把密钥写入 Web 构建产物。
- 开启多用户模式或公网访问前，配置认证、受信任代理、HTTPS 和备份策略。
